# Work 결과물 생성 구조 및 다이어그램 사용 안내

## 1. 전체 구조

```text
Work(작업 공간)
└─ 플러그인(기능 묶음)
   ├─ 스킬(작업 절차·품질 기준·사용 규칙)
   └─ 앱/도구(실제 실행 기능)
      └─ 결과물
         ├─ 문서(DOCX 등)
         ├─ 프레젠테이션(PPTX 등)
         ├─ 표/데이터(XLSX 등)
         ├─ 인터랙티브 시각화(HTML)
         └─ 이미지(PNG/JPG 등, 이미지 도구가 노출된 경우)
```

## 2. 각 요소의 역할

| 요소 | 역할 | 예시 |
|---|---|---|
| Work | 사용자의 요청을 해석하고 여러 단계를 조율하는 작업 공간 | 기획, 검토, 파일 작성 |
| 플러그인 | 특정 업무 영역에 필요한 기능과 연결을 묶은 패키지 | Presentations, Documents |
| 스킬 | 작업 방법, 형식, 검수 기준을 정한 지침서 | 슬라이드 제작 규칙, 문서 렌더링 규칙 |
| 앱/도구 | 실제로 파일을 만들거나 변환·렌더링하는 실행 기능 | DOCX 생성, PPTX 생성, 시각화 렌더링 |
| 결과물 | 사용자가 다운로드·공유·재사용하는 최종 산출물 | DOCX, PPTX, XLSX, HTML, PNG |

## 3. 결과물이 만들어지는 흐름

```text
요청
  ↓
Work가 작업 유형과 필요한 플러그인을 판단
  ↓
플러그인의 스킬이 작업 절차와 품질 기준을 적용
  ↓
실행 도구가 파일 또는 시각화를 생성
  ↓
검수·수정
  ↓
최종 결과물 전달
```

## 4. 이번 예시의 매핑

| 요청 | 사용 기능 | 결과물 |
|---|---|---|
| Work·플러그인·스킬 관계 시각화 | Visualize 스킬 | 인터랙티브 HTML 다이어그램 |
| 정적 그림으로 보관 | 이미지 생성 도구 또는 화면 캡처 | PNG/JPG |
| Work에 구조를 설명 | Markdown | 이 문서 또는 채팅에 붙여넣는 설명문 |

## 5. Work에 가져가는 방법

1. 이 Markdown 파일을 Work 대화에 첨부합니다.
2. 필요하면 다이어그램 화면을 PNG로 캡처해 함께 첨부합니다.
3. 다음과 같이 요청합니다.

> 첨부한 Markdown과 다이어그램을 기준으로 Work에서 결과물이 만들어지는 구조를 이해하고, 이후 문서·프레젠테이션·시각화 작업을 할 때 각 단계의 역할과 최종 산출물 형식을 구분해서 설명해줘.

## 6. 형식 선택 기준

- 구조와 규칙을 재사용할 목적이면 **Markdown**이 적합합니다.
- 사람에게 빠르게 보여주거나 발표 자료에 넣을 목적이면 **PNG 캡처본**이 적합합니다.
- 가장 안전한 방식은 **Markdown + PNG를 함께 첨부**하는 것입니다.
