# 02. AI를 이해하는 가장 간단한 그림

## 기존 소프트웨어

> 입력 → 규칙 → 결과

정해진 규칙에 따라 결과를 계산한다.

## 전통적인 AI

> 데이터 → 학습 → 분류 / 예측

예:

- 이 사진은 고양이인가?
- 이 고객은 이탈할 가능성이 있는가?
- 내일 매출은 얼마인가?

## 생성형 AI

> 입력 → 학습된 패턴 → 새로운 콘텐츠 생성

예:

- 글쓰기
- 요약
- 번역
- 이미지 생성
- 코드 생성
- 음성 생성

### 핵심

**AI는 '정답 데이터베이스'와 같은 방식으로 작동하지 않는다.**

# 03. 생성형 AI의 본질

## Generative AI

생성형 AI는 학습한 데이터의 패턴을 바탕으로  
**새로운 콘텐츠를 생성하는 AI**다.

텍스트뿐 아니라

`텍스트 · 이미지 · 음성 · 영상 · 코드`

등 다양한 형태를 생성할 수 있다.

### 아주 단순하게 보면

> "지금까지 학습한 패턴을 바탕으로  
> 다음에 올 가능성이 높은 것을 계속 만들어 간다."

NIST 역시 생성형 AI의 주요 특성을  
학습 데이터의 구조와 특성을 바탕으로 새로운 합성 콘텐츠를 생성하는 것으로 설명한다.

# 05. GPT는 '검색엔진'이 아니다

## 아주 중요한 오해

### 질문

> "서울의 현재 인구는 얼마야?"

### 검색 시스템

웹이나 데이터베이스에서  
관련 정보를 **찾는다.**

### 언어모델

주어진 입력과 맥락을 바탕으로  
다음에 올 토큰을 예측하면서  
**응답을 생성한다.**

OpenAI는 GPT 계열 모델을  
문맥에서 다음 토큰을 예측하는 방식으로 사전학습된 Transformer 계열 모델로 설명한다.

---

# 06. 검색과 생성의 차이

| 검색(Search) | 생성(Generation) |
|---|---|
| 정보를 찾는다 | 응답을 만든다 |
| 원문/문서에 접근 | 학습된 패턴 활용 |
| 출처 확인이 상대적으로 쉽다 | 출처가 자동으로 보장되지 않는다 |
| 최신 정보에 강함 | 모델의 학습 범위에 영향을 받음 |
| 검색 결과를 제공 | 문장을 새롭게 구성 |

## 중요한 변화

하지만 **2026년의 AI는 둘을 결합한다.**

> 검색 → 정보 확보 → 생성 → 출처 기반 답변

이것이 바로 **RAG와 AI 에이전트**로 이어진다.

# 07. 그렇다면 AI는 '생각'하는가?

## 여기서 주의해야 한다

사람처럼

> "나는 이 사실을 알고 있다."

라고 기억하는 방식과

언어모델의

> "이 문맥에서는 이런 토큰이 나올 가능성이 높다."

는 전혀 같은 것이 아니다.

### 그래서 AI를 이렇게 이해하면 좋다.

**AI = 거대한 지식 저장소**

라고 단순하게 생각하기보다,

**AI = 학습된 패턴을 바탕으로  
입력에 반응하여 출력을 만들어 내는 모델**

이라고 이해하는 것이 정확하다.

# 08. AI 할루시네이션이란?

# Hallucination

AI가

> **사실이 아닌 내용을  
> 사실인 것처럼 그럴듯하게 생성하는 현상**

을 흔히 할루시네이션이라고 부른다.

NIST는 이를 **confabulation**이라는 표현으로 설명하면서,

> 자신 있게 표현하지만 잘못되었거나 거짓인 내용을 생성하는 현상

이라고 설명한다.

### 문제는?

**틀린데도 매우 그럴듯하다.**

# 09. 왜 AI는 틀릴까?

## AI에게는 이것이 중요하다.

> "사실인가?"

보다

> "이 문맥에서 어떤 출력이 적절한가?"

가 모델의 기본 생성 과정에 가깝다.

그래서

### 학습 데이터에 오류가 있거나
### 정보가 부족하거나
### 질문이 모호하거나
### 최신 정보가 필요하거나
### 존재하지 않는 것을 물어보면

그럴듯한 답을 만들어낼 수 있다.

### 핵심 문장

> **AI의 유창함 ≠ AI의 사실성**

# 11. RAG란 무엇인가?

# Retrieval-Augmented Generation

## 검색 증강 생성

쉽게 말하면

> **AI가 답하기 전에 필요한 자료를 찾아서  
> 그 자료를 참고하게 만드는 방식**

이다.

### 기본 구조

```text
사용자 질문
     ↓
관련 자료 검색
     ↓
관련 문서/정보 확보
     ↓
AI에게 Context로 제공
     ↓
답변 생성
```

RAG의 기본 연구는 2020년 Lewis et al.의  
「Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks」에서 제시되었으며,

**검색기(Retriever) + 생성기(Generator)​**를 결합해 외부 지식을 활용하는 구조를 제안했다.

---

# 12. RAG의 핵심 원리

## AI에게 '외부 기억장치'를 붙인다

### 기존 LLM

```text
질문
 ↓
모델의 학습된 지식
 ↓
답변
```

### RAG

```text
질문
 ↓
관련 문서 검색
 ↓
Context
 ↓
LLM
 ↓
답변
```

### 쉽게 비유하면

> LLM = 글을 잘 쓰는 사람  
> RAG = 책장 + 검색 시스템

### 중요한 점

RAG가 있다고 해서  
**무조건 정답이 되는 것은 아니다.**

검색한 문서가 잘못되면  
AI도 잘못된 답을 만들 수 있다.

---

# 13. RAG와 검색엔진은 무엇이 다른가?

## 검색엔진

> "관련 자료를 찾아주세요."

결과:

```text
문서 A
문서 B
문서 C
```

## RAG

> "관련 자료를 찾아서  
> 그 자료를 근거로 답변해주세요."

결과:

```text
검색
 ↓
관련 정보
 ↓
AI의 해석
 ↓
답변
```

### 한 문장으로

**검색은 정보를 찾고,  
RAG는 찾은 정보를 생성 과정에 연결한다.**

---

# 14. 그래서 프롬프트가 중요하다

## 프롬프트란?

AI에게 전달하는

> **질문 · 지시 · 목표 · 맥락 · 제약조건**

이다.

좋은 프롬프트는 단순히

> "자세하게 설명해줘."

가 아니다.

### 핵심은

**AI가 무엇을 해야 하는지  
사람이 의도한 방향을 충분히 설명하는 것**

이다.

OpenAI, Google, Anthropic의 최신 프롬프트 가이드에서도  
명확한 목표, 맥락, 출력 형식, 제약조건, 예시를 제공하는 방식을 공통적으로 강조한다.

# 15. 프롬프트 6원칙

## 우리가 사용할 6가지 프레임

> 이것은 특정 회사의 공식 표준이 아니라  
> 실무 교육에서 사용할 수 있도록 정리한 **6요소 프레임**이다.

### ① 역할
**누가 답할 것인가?**

### ② 목표
**무엇을 할 것인가?**

### ③ 맥락
**무엇을 알고 있어야 하는가?**

### ④ 제약
**무엇을 지켜야 하는가?**

### ⑤ 예시
**어떤 결과가 좋은 결과인가?**

### ⑥ 출력
**어떤 형태로 결과를 받을 것인가?**

# 16. 나쁜 프롬프트 vs 좋은 프롬프트

## ❌ 나쁜 요청

```text
복지관 홍보문 만들어줘.
```

## ✅ 구조화된 요청

```text
[역할]
너는 종합사회복지관 홍보 담당자다.

[목표]
어르신 대상 프로그램 참여자를 모집하는
홍보문을 작성한다.

[맥락]
지역주민을 대상으로 하는 프로그램이며
전문용어를 사용하지 않는다.

[제약]
300자 이내
따뜻하고 친근한 분위기
과장된 표현 금지

[출력]
제목 3개
본문 1개
홍보 문구 3개
```

### 차이는?

**질문을 길게 쓴 것이 아니라  
AI가 판단해야 할 조건을 명확하게 만든 것이다.**

# 17. 프롬프트의 핵심은 '말빨'이 아니다

## 흔한 오해

> "프롬프트를 잘 쓰려면  
> 특별한 주문이 있어야 한다."

실제로 중요한 것은

### 사고를 구조화하는 능력

```text
무엇을 원하는가?
      ↓
누구를 위한 것인가?
      ↓
어떤 자료가 필요한가?
      ↓
무엇을 제한할 것인가?
      ↓
어떤 결과를 원하는가?
      ↓
어떻게 검증할 것인가?
```

### 그래서

**프롬프트 능력  
= 사고를 AI가 이해할 수 있는 구조로 변환하는 능력**

# 19. AI 에이전트 시대

## AI Agent란?

단순히 답변을 생성하는 AI를 넘어

### 목표를 이해하고

↓

### 작업을 계획하고

↓

### 필요한 도구를 사용하고

↓

### 여러 단계를 실행하고

↓

### 결과를 확인하고

↓

### 다음 행동을 결정하는 시스템

이다.

OpenAI는 현재 Agents를  
**계획하고, 도구를 호출하고, 전문가끼리 협업하며, 여러 단계의 작업을 완료할 수 있는 애플리케이션​**으로 설명한다.

OECD의 2026년 보고서 역시 agentic AI의 주요 특징으로  
목표 지향성, 자율성, 작업 분해, 여러 에이전트 간 협업, 장시간의 지속적인 작업 수행 등을 제시한다.

```text
검색
  ↓
생성
  ↓
검색 + 생성
  ↓
RAG
  ↓
도구 사용
  ↓
에이전트
  ↓
여러 AI가 협업하는 Agentic AI
```

## 그리고 인간의 역할도 바뀐다.

### 과거

> "AI에게 무엇을 입력할까?"

### 지금

> "AI에게 어떤 목표와 맥락을 줄까?"

### 앞으로

> "AI가 어떤 자료와 도구를 사용해서  
> 어떤 일을 수행하도록 설계할까?"

# 오늘의 핵심 문장

## AI는 정답을 꺼내주는 기계가 아니다.

**AI는 학습된 패턴을 바탕으로  
새로운 결과를 생성하는 시스템이다.**

그래서 우리는

> **생성 → 검증 → 검색 → RAG → 프롬프트 → 에이전트**

라는 흐름을 이해해야 한다.

### 결국 AI 시대의 핵심 역량은

# "AI를 잘 쓰는 것"이 아니라
# "AI에게 일을 잘 설계해 주는 것"
