# Reusable trigger workflow

이 문서는 별도 Codex Skill 없이도 같은 품질 기준으로 덱 제작을 반복하기 위한 4단계 요청문이다. 각 단계는 결과를 확인한 뒤 다음 단계로 넘긴다.

## 1. ANALYZE — 재료와 흐름 분석

```text
이 프로젝트를 Slidev 강의 덱으로 만들 준비를 해줘.

입력:
- 강의 흐름: [여기에 세션 목표, 순서, 시간, 전달할 핵심을 적는다]
- 에셋 폴더: [public 경로]
- 참고 자료: [문서, 링크, 이미지 설명]

먼저 코드를 만들지 말고 다음만 해줘.
1. 에셋을 유형·주제·권장 역할·주의점으로 분류한다.
2. 각 에셋을 어느 슬라이드에서 어떤 연출로 쓸지 제안한다.
3. 강의 흐름을 슬라이드 시퀀스로 재구성한다.
4. 비어 있는 자료와 확인이 필요한 사실을 표시한다.
5. asset-manifest.yaml과 deck-brief.yaml에 들어갈 초안을 제시한다.

lecture-deck-kit의 visual contract를 기준으로 삼고, 이 단계에서는 슬라이드 파일을 수정하지 말고 멈춰라.
```

## 2. APPROVE — 연출과 구조 확정

```text
위 분석을 바탕으로 다음 두 가지를 확정안으로 정리해줘.

1. 슬라이드별 목적, 한 문장 메시지, 주자료, 보조자료, 등장 순서
2. 각 슬라이드의 레이아웃 패턴
   - cover / section divider / reveal list / comparison / media / demo cue / takeaway 중 선택
   - 필요한 경우 새 컴포넌트 후보를 제안

텍스트를 과도하게 채우지 말고, 설명할 내용과 화면에 보여줄 내용을 분리해줘.
사용자가 수정할 수 있도록 확정이 필요한 항목을 마지막에 짧게 묻고 멈춰라.
```

## 3. BUILD — Slidev 초안 생성

```text
확정한 흐름과 asset manifest를 사용해서 lecture-deck-kit 기반의 Slidev 초안을 만들어줘.

규칙:
- 기존 visual contract, tokens, transitions, components를 우선 사용한다.
- 에셋은 public 경로를 통해 실제로 연결한다.
- 새 컴포넌트가 필요하면 먼저 기존 컴포넌트 조합으로 해결하고, 정말 필요할 때만 추가한다.
- 슬라이드마다 하나의 중심 메시지만 둔다.
- 발표자가 개입할 지점은 DemoCue 또는 speaker note로 표시한다.
- 확인되지 않은 정보나 숫자는 사실처럼 작성하지 않는다.

완료 후 수정한 파일, 사용한 에셋, 보류한 항목을 요약하고 멈춰라.
```

## 4. QA — 빌드와 시각 검수

```text
생성한 Slidev 덱을 검수해줘.

1. pnpm build를 실행한다.
2. 모든 슬라이드를 실제 화면으로 확인한다.
3. 다음을 점검한다: 글자 잘림, 겹침, 대비, 빈 공간, 이미지 비율, 아이콘 로딩, v-click 순서, 전환, reduced-motion 대응
4. 문제를 심각도 순으로 정리하고, 고칠 수 있는 문제는 수정한다.
5. 마지막에 남은 리스크와 발표자가 직접 확인할 항목만 알려줘.
```

반복 제작에서는 1단계와 2단계를 사용자가 승인하는 체크포인트로 남기는 것이 좋다. 나중에 이 흐름이 안정되면 이 문서를 Codex Skill로 감싸 자동 호출할 수 있다.
